# Botの流動性に出資する

マーケットを作成した直後、注文板は空です。初期トレーダーが取引相手を見つけられるように、bitCasterは自動マーケットメーカー（AMM）を動かし、注文板に初期のBidとAskを提示できます。

出資は任意です。マーケット作成後、ウィザードは資金提供画面を表示し、**No liquidity**、**Minimal**、**Standard**、**Deep**、またはカスタム予算を選べます。二項マーケットのプリセットは **10,000 / 100,000 / 500,000 sats** という丸い金額です。カテゴリカルマーケットでは、有料ティアに `log2(アウトカム数)` が掛けられます。

どのユーザーも、マーケット詳細ページの `LIQUIDITY` タブから後続の資金提供を送信できます。資金提供はマーケット作成者だけに限定されません。

ウィザードは、選択した予算を推定初期板厚としてプレビューします。Botが片側あたりおよそ何段の価格レベルを出せるか、各レベルがおよそ何枚のshareになるかを表示します。このプレビューはmint手数料前の概算なので、実際の提示深度はこれより低くなる場合があります。

## 何に使われるのか

入金はそのマーケットのAMM容量になります。現在のAMMはLMSR戦略を使います。最初に承認された入金でBotは均一な中立状態から開始します。入金に開始確率を含めることはなく、公開マーケット価格も設定しません。

マーケットカードと詳細ページでは、承認済みのBot資金を **Bot Budget** として表示します。後から承認された入金があると、この合計は増加します。これはライブの注文板流動性や残り在庫ではありません。

各入金は**返金不可**です。マーケットが解決されるまでマーケットメイクにコミットされます。後続の入金はBotの再価格設定を行わずに容量を増やします。入金者に確率を持つポジション、引き出し権、残余請求権、作成者としての利益分配請求権は発生しません。

ユーザー向けにはマーケットをsatsで表示します。内部会計と公開マーケットサマリの `*Subunits` ワイヤフィールドでは **msat** を使います。

## 資金提供フロー

1. マーケットを作成します。登録には資金提供も開始確率も含めません。
2. 資金提供ティアを選ぶか、No liquidityを選びます。
3. 資金提供する場合は、設定済みMintが発行したCashu支払いを送信します。
4. 支払いが承認されるまで入金ステータスを確認します。最初に承認された入金でBotが有効になります。後から容量を増やすために、このフローを繰り返せます。

## ウィザードを閉じた場合

ウィザードを閉じてもマーケットは取り消されません。マーケットは作成済みのまま残り、人間の注文は受け付けられます。No liquidityを選んだ場合、または資金提供がまだ完了していない場合、自動マーケットメーカーは承認された入金で有効になるまで建値しません。

選択した実行可能な注文板にBidもAskもない場合、`BUY` と `SELL` タブには流動性がないことを示すメッセージと `LIQUIDITY` を開く操作だけを表示します。資金提供が完了しても、流動性が存在するとは表示しません。実行可能な注文板が空でなくなった後にだけ、通常の注文フォームを表示します。

## トレードオフ

小さな予算では建値が薄くなり、情報を持つトレーダーの取引で価格が動きやすくなります。大きな予算ではより深い建値になりますが、返金不可のリスク資本も増えます。Botは均一な中立状態から開始するため、作成者の確率入力はありません。

AMM流動性は主に取引を立ち上げるためのものです。長期的には、人間やプロのマーケットメイカーが、自動建値より狭く、より情報の入った流動性を提供するのが望ましい状態です。

資金提供は公開マーケット価格を設定しません。公開価格を設定できるのは承認済みの取引だけです。最初の承認済み取引の前はマーケットに価格がないため、クライアントは **No trades yet** または em dash を表示します。Bid/Askのミッドポイントは注文入力の参考値にすぎません。
