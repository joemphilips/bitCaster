# マーケットの作成

多くの予測市場プラットフォームでは、どのマーケットが存在するかを決めるのは運営者だけです。bitCasterは異なります。誰でも、いつでも、あらゆるテーマのマーケットを作成できます。必要なのは、イベントを証明するオラクルと、マーケットのメタデータです。

マーケットの作成とは、イベントの内容を定義し、結果を証明する人（オラクル）を決め、可能なアウトカムを登録することです。マーケット登録は通常の `Open` 登録です。開始確率や入金を登録時に指定することはなく、登録時にマーケット価格も設定しません。

## オラクルの選択

bitCasterのすべてのマーケットは、少なくとも1つの**オラクルアナウンスメント**に紐づいています。これは、オラクルが特定の将来のイベントについてアテステーションを行うという署名付きの宣言です。アナウンスメントは標準的なDLCオラクルフォーマットに従います。Nostrイベント（Kind 88）として公開すると発見性と監査可能性が高まりますが、リレーが利用できない場合でも、署名済みアナウンスメントをミントとマッチングエンジンへ直接登録できます。

賭けたいイベントに既にオラクルアナウンスメントがある場合、例えばBitcoin価格のアテステーションを毎日公開している有名なDLCオラクルがあれば、それを選択するだけで済みます。

しかし実際には、興味深いマーケットのほとんどは、既存のオラクルがまだアナウンスしていない新しいイベントに関するものです。「X社はQ3までに機能Yをリリースするか？」「7月1日に東京で雨が降るか？」といった問いは、たいていまだ誰もアテステーションすることをコミットしていません。この場合、マーケット作成者は同時にオラクルにもなります。自分のオラクル鍵を設定し、自らアナウンスメントを作成して、イベントが解決した際に結果を証明することを約束します。

予測市場では必ずオラクルに対する信頼が発生します。誰を信頼するかの根本的な選択は各トレーダーに委ねられています。

## ベースアセット

すべてのマーケットには表示用の**ベースアセット**があり、ユーザーが入力する資金・ステーク・建値支払いの単位を決定します。ワイヤ上の金額とproof合計は、マーケットの担保サブユニットを使います。現在のプロダクトが対応する値は1つです。

- **sat** — ユーザーはサトシ単位で入力します。担保proofと公開APIのサブユニットフィールドはmsatを使います。

USD、JPY、およびその他のプロダクト担保単位は利用できません。

bitCasterは対象となる条件が `msat` 担保を使うことをミントに確認します。ミントがまだ単位を確認できない場合、マーケット登録は再試行可能なエラーを返します。ミントに条件が登録されてから再度お試しください。NUT-CTFでは、`sat` は表示用アセットであり担保proof単位ではありません。マーケットはmsatで登録され、proof金額もmsatで合計します。

## 価格分母

すべてのマーケットには**価格分母**（D）があります。現在のYes/Noとカテゴリカルマーケットでは `D=10000` を使います。これにより `0.01%` の価格精度となり、アプリは **53.27%** のように小数第2位までの価格を表示できます。数値マーケットの作成と取引は現在利用できません。数値用の `D=1000000` は、将来の数値取引表現のために予約されています。

- **価格の細かさ。** 価格は1からD−1の整数で表されるため、最小の価格変動は1/Dです。
- **1枚あたりの額面。** Dは価格精度を決めます。カテゴリカルマーケットの1枚は、勝った場合 **10 sats** を受け取ります。
- **決済精度。** すべてのマーケット担保は **msat** で会計されます。

価格分母と1枚あたりの額面は、マーケット登録後に変更できません。

## マーケットに資金提供する

マーケット作成が成功すると、bitCasterは任意の**マーケットメイカーに資金提供**ステップを表示します。これは作成後の独立したフローです。資金提供を行うと、そのマーケットの自動マーケットメーカーが注文板にBidとAskを出すための容量を持てます。作成後に承認された入金を複数回送ることができます。

入金では `fundAmm` を使い、サービスはこれを引き出し可能なユーザー残高ではなくAMMの建値予算として扱います。資金提供者に確率を持つポジションや特別な配当は発生しません。

マーケットメイカーへの資金提供はsatsで表示します。内部会計と公開 `*Subunits` ワイヤフィールドではmsatを使います。USD、JPY、およびその他のプロダクト担保単位は利用できません。

資金提供ステップには、No liquidity、Minimal、Standard、Deep、Customの予算があります。二項マーケットのプリセットは **10,000 / 100,000 / 500,000 sats** という丸い金額で表示されます。カテゴリカルマーケットでは、有料ティアに `log2(アウトカム数)` が掛けられます。最初に承認された入金でBotは均一な技術状態から開始します。後続の入金は容量を増やしますが、その開始状態や固定されたリスクパラメータを変更しません。

ウィザードは、選択した予算で見込まれる初期板厚もプレビューします。Botが片側あたりおよそ何段の価格レベルを出せるか、各レベルがおよそ何枚のshareになるかを表示します。このプレビューはmint手数料前の概算なので、実際の提示深度はこれより低くなる場合があります。

**No liquidity**を選ぶと、マーケットはBotによる建値なしで利用可能になり、人間のメイカーが流動性を提供する必要があります。選択した実行可能な注文板にBidもAskもない場合、`BUY` と `SELL` タブには流動性がないことを示すメッセージと `LIQUIDITY` を開く操作だけを表示します。`LIQUIDITY` タブではこの作成後の資金提供フローを使います。非常に小さいカスタム予算では、流動性が薄いことを示す警告が表示される場合があります。

資金提供は公開マーケット価格を設定しません。公開価格を設定できるのは承認済みの取引だけです。最初の承認済み取引の前はマーケットに価格がないため、アプリは **No trades yet** または em dash を表示します。Bid/Askのミッドポイントは注文入力の参考値にすぎません。

AMMによる資金提供は、取引を立ち上げるためのものです。人間のマーケットメイカーを永続的に置き換えるためのものではありません。マーケットが成熟するにつれて、人間やプロのマーケットメイカーが、初期AMMの建値をより狭く、より情報の入った流動性で置き換えていくのが理想です。

資金提供の確認前に表示される開示文:

> この入金は返金不可です。市場が収束した場合、予算は価格に情報をもたらしたトレーダーへの支払いに使われる見込みです。クローズ時の残額はオペレーター収益となります。

## マーケットのライフサイクル

マーケットは2つのイベントのいずれかが到来するまで開いています。1つ目は、オラクルが発表したデッドライン — オラクルがアウトカムを証明することをコミットした時刻です。2つ目はアテステーション自体で、イベントがデッドラインより早く解決した場合は、より早く到着することがあります。どちらか先に到来した方がマーケットを閉じます。

マーケットが閉じた後は、新規の注文や入金は受け付けられません。それ以降は取引は終了し、勝者が条件付きトークンをecashに交換する償還フェーズに入ります。償還ウィンドウはマーケットごとではなくミントごとに設定され、そのミントが発行するすべてのマーケットに同じ長さが適用されます。
