# 市場の結果確定

市場の取引が終了しても、どの結果が的中したか決まっているとは限りません。
払戻しを受ける前に、取引の状態とオラクルの結果を確認してください。

**オラクル**は、イベントの結果に署名する主体です。署名された結果を
**アテステーション**と呼びます。ミントはこの署名を検証し、
どの条件付きトークンが的中時の払戻しを受けられるかを判断します。
これが市場の結果確定です。

## 取引の前に

質問、選択できる結果、オラクルの識別情報、期限を確認してください。
ミントの償還期間と、結果がない場合のポリシーも確認してください。
オラクルは市場の作成時に固定されます。

有効な署名から分かるのは、誰が結果に署名したかです。
結果が事実と一致することや、質問が明確であることの証明にはなりません。
根拠と判断を信頼できるオラクルを選んでください。
bitCaster は、この判断をプラットフォームの信頼スコアで代替しません。

## 取引が終了する時点

市場が有効なオラクルの結果を受け付けると、新しい注文と資金提供を終了します。
結果がないまま、発表済みの期限に達して取引を終了する場合もあります。
期限による終了だけでは、的中したトークンは決まりません。

期限で取引が終了した後も、検証済みの結果を受け付けることができます。
この結果によって的中したアウトカムが決まります。取引は再開せず、最初の終了時刻も変わりません。
検証済みの結果がない市場は、取引終了後も結果未確定です。

オラクルは Nostr を通じてアテステーションを公開できます。
作成者は署名済みのアテステーションをマッチングエンジンに直接送信することもできます。
直接送信する場合も、署名の検証は必要です。
Nostr リレーはメッセージを運びますが、結果の有効性を判断する主体ではありません。

ミントが結果を受け付けると、的中したトークンを額面で償還できます。
ただし、ミントの手数料と償還期間が適用されます。
外れたトークンは的中時の払戻しを受けられません。
通常の YES/NO 市場では、署名された結果に対応するトークンだけが的中します。

的中したトークンを無期限に償還できるとは限りません。
償還期間は、ミント内の市場で共通のポリシーです。
取引の前と償還の前に、適用される期限を確認してください。

## ブラウザーのオラクルとして結果を報告する

クリエイターページで「あなたのマーケット」を開いてください。
自己オラクルのマーケットでは、登録済みのアウトカムを選び、
「マーケットをクローズ」を選択してください。
「この市場を解決」ダイアログに、選択したアウトカムが表示されます。
任意の公開説明をプレーンテキストで追加できます。
説明の上限は UTF-8 で4096バイトです。個人情報や秘密情報を含めないでください。
「保存した解決を確認して配信」を選択すると、選択内容を保存して配信を開始します。

選択内容を保存すると、アウトカムと元の説明の下書きは変更できません。
ブラウザーは、配信前に正確な署名済み kind-89 の結果を保持します。
ブラウザーの保存機能を有効にしてください。
配信が未完了の場合は、「保存した解決を再試行」を選び、ダイアログで確認してください。
再試行は保存済みの結果を配信します。
別の kind-89 イベントへの署名や、新しいアナウンスの作成は行いません。
再試行は、保存済みの署名済みイベントだけを送信します。
署名済みの説明が保存されていない場合、再試行で説明を作成しません。
元の説明の下書きは保存したままです。
正確な保存済みの結果の配信には、オラクルの署名鍵は不要です。

エンジン、リレー、任意の説明の進捗は、それぞれ確認してください。
「エンジン確認済み」は、正確な結果について検証済みのエンジンの証拠があることを示します。
「リレー確認済み」は、リレーが結果の受信を確認したことを示します。
どちらの確認も、もう一方の確認やミントでの償還完了を保証しません。
説明の失敗は、結果の配信を妨げません。
検証済みの説明は、クローズしたマーケットのページに表示される場合があります。
有料の取引コメントとは別です。

期限でクローズし、検証済みの結果がないマーケットでも、作成者は結果を報告できます。
取引終了の状態だけでは、的中したトークンは決まらず、払戻しも保証されません。
後から検証済みの結果が届いても、取引は再開しません。

## ネイティブオラクルとして結果を報告する

オラクルアナウンスを作成した daemon プロファイルを使ってください。
登録済みのアウトカムを一つ選びます。短いプレーンテキストの説明も付けられます。

```bash
bitcaster-cli market close --condition-id <condition-id> --outcome Yes --explanation "The announced event has finished." --trust-engine-url
bitcaster-cli market resolution-status <condition-id>
bitcaster-cli market close --condition-id <condition-id> --retry --trust-engine-url
```

`Yes` を正確なアウトカム名に置き換えてください。
`--trust-engine-url` は、信頼するエンジン URL にだけ使ってください。
`--explanation @explanation.txt` は UTF-8 ファイルを読み込みます。
説明の上限は UTF-8 で4096バイトです。
説明は、署名済みの結果、払戻し、取引コメントの順位を変更しません。
説明は、独立した署名済み kind-1111 イベントです。
ルートは元の kind-88 アナウンスです。親は正確な kind-89 アテステーションです。

クライアントは、送信前に選択したアウトカムと署名済みイベントを保存します。
元の daemon プロファイルを保持してください。
別のアウトカムを選ばず、保存済みの結果を再試行してください。
`--retry` にアウトカムや説明は指定しません。
保存済みの署名済みイベントを再利用します。
説明の準備に失敗した場合は、元の保存済み下書きの準備を完了できます。
再起動後も、市場の再作成や別の登録手数料は必要ありません。

`resolution-status` は、選択したアウトカムと二つの公開イベント ID を返します。
`attestationPrepared` と `explanationPrepared` は、署名済みイベントの保存状態を示します。
`relayPublished` と `explanationRelayPublished` は、リレーによる受信確認を示します。
`engineSynchronized` は、正確な結果について検証済みのマッチングエンジンの証拠があることを示します。
`explanationDraftSaved` は、元の下書きが存在するかだけを示します。
リレーへの送信とエンジンとの同期は独立しています。
コマンドが成功しても、返された `record` と `failures` を確認してください。
`Closed` はエンジンの証拠を確認したことを示します。
両方のリレー送信やミントでの償還の完了を示すものではありません。
説明の失敗によって、有効な結果確定が無効になることはありません。

署名済みイベントを渡す `market close --condition-id <condition-id> --attestation @attestation.json`
も引き続き使えます。この形式はネイティブの説明を作成しません。

## オラクルが結果を公開しない場合

初回リリースには、アテステーションがない場合の事前に決まった返金規則はありません。
ミント運営者は、公開済みのポリシーに従って返金結果を選択できます。
期限を過ぎても、即時の返金や特定の返金額が保証されるわけではありません。
資金を投入する前に、そのポリシーを読んでください。

## 払戻しを受ける

償還とは、的中した条件付きトークンを同じミントの通常の ecash に交換することです。
Bitcoin の出金とは別です。ウォレットは払戻し額を sats で表示します。
Bitcoin を出金するには、ミントが対応する BOLT11 Lightning 出金フローを使ってください。

償還結果が判明するまで、ウォレットの記録を保持してください。
リクエスト中に接続が切れた場合、トークンが未使用だと判断せず、既存の操作を確認してください。
[決済と回復](/ja/user-guide/core-concepts/atomic-swap/)を参照してください。

### ブラウザーを使う場合

証拠を取得できる場合、受け取り時に指定されたオラクルの証拠を検証します。
証拠がない場合、取得できない場合、または無効な場合は、次の警告を表示します。
「ミントはこの結果を報告していますが、指定されたオラクルの証拠はまだ検証できていません。」
警告が表示されても、受け取りは実行できます。
ウォレットは、受け取った各プルーフを検証してから払戻しを記録します。
ミントの拒否だけでは、保有しているトークンが外れたことの証明にはなりません。
削除の処理が受け取りを通じてポジションを確認する場合も、同じ警告を表示します。
メッセージは、閉じるまで表示されます。

復元した拒否記録に、外れたことを示す検証済みの証拠がない場合があります。
ウォレットはその条件付きトークンを保持し、保持している金額を表示します。
この未検証の保持状態にあるトークンは、受け取り、売却、削除ができません。

ポートフォリオを開き、的中したポジションの受け取りを選択してください。
受け取りは、複数の部分に分かれて完了することがあります。
別の部分で失敗しても、完了した払戻しはウォレットに残ります。

受け取りが保留中の場合、ウォレットのデータを保持し、受け取りを再試行してください。
保留中の状態は、再読み込み後も表示されます。
再試行は未完了の部分を復旧します。完了した払戻しが二重に加算されることはありません。
接続が切れても、ミントが支払いを拒否したとは限りません。

外れたポジションを削除するには、削除を選択して確認してください。
ウォレットは、トークンが払戻しを受けられないことを確認してから削除します。
結果が不明な場合は、トークンを保持します。
ミントから払戻しがあった場合は、その支払いを保持して削除を停止します。

暗号化バックアップが有効な場合、削除に時間がかかることがあります。
削除が保留中のポジションは表示され続けます。
完了するまでウォレットのデータを保持してください。
エクスポートしたコピーや、別のブラウザーに残したコピーは削除されません。

削除に失敗した場合は、メッセージに表示される削除参照を保存してください。
削除参照は、失敗した処理段階と実行を識別します。
問題を報告するときは、この参照を添えてください。
復元フレーズ、秘密鍵、ecash トークンは共有しないでください。

### CLI を使う場合

`wallet claim <condition-id> <outcome-collection>` の JSON 出力には、
各部分の `oracleEvidence` 状態が含まれます。
状態は `verified` または `unverified` です。
`unverified` の場合は、理由とブラウザーと同じ警告が含まれます。
対象のアウトカム集合が外れたことを検証済みの証拠で確認できない場合、
拒否された部分は保留中のままになります。
ウォレットのデータを保持し、既存の復旧操作を使用してください。

ネイティブ daemon は、ユーザーが償還と保有記録の整理を承認するまで、
結果確定済みの条件に対応する proof を保持します。
次のコマンドで、実行内容とミント手数料の見積額を確認できます。

```sh
bitcaster-cli wallet retire-condition <condition-id>
```

実行を承認するには `--acknowledge` を追加します。的中した proof が償還されます。
外れた proof と、償還費用が価値に見合わない proof は監査記録として表示され続けます。
このコマンドが黙って削除することはありません。

検証済みのオラクルアテステーションの受信後にこの処理を自動で実行するには、
`~/.bitcaster/config.json` の `daemon.autoRetireResolvedConditionInventory` を
`true` に設定してください。既定値は `false` です。変更後に daemon を再起動してください。
