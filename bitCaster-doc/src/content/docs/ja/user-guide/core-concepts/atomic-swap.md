# アトミック決済

注文の送信と取引の完了は別です。マッチングエンジンが相手の注文を見つけます。その後、Cashu ミントが認可された資金とシェアを交換します。ミントは決済グループごとの交換を 1 件の操作として完了します。交換の片側だけを完了することはありません。これが**アトミック決済**です。

## 確認する前に

数量、取引代金の見積もり、別途かかる手数料を確認してください。
エンジンは、同意した取引代金より支払いが増える取引や、受取額が減る取引を拒否します。
同意した最悪約定価格も確認します。これらの制限は、ウォレットの準備手数料や返金手数料を
なくすものではありません。取引が完了しなくても、準備に手数料がかかる場合があります。

取引の概要に Participation Score の行が表示される場合もあります。Participation Score は
スパム対策の手数料です。注文板を使う注文には、bitCaster が数 sats 分の Score を請求します。
この行には、この注文で請求する Score を表示します。Score の残高で請求額を支払えない場合は、
**確認時の Score チャージ（残高として保持）** の行も表示されます。この行には、注文を確定したときに
アプリがウォレットの通常の sats で購入する Score を表示します。購入額は不足額より大きい場合があります。
注文で使わなかった Score は残高に残り、以降の注文に使えます。取引の合計額には、これらの行を含みません。
Score は返金できません。請求額とチャージの規則は、[Participation Score](/ja/technical/architecture/trading-model/#participation-score)を参照してください。

保有するシェアをすべて売るには、準備手数料に使う通常の sats を残してください。
ウォレットは、売るシェアを減らさずに sats で準備手数料を支払えます。
準備は売却より先に行うため、売却代金ではこの手数料を支払えません。

このリリースでは、Web アプリと CLI の両方が fill-or-kill（FOK）注文を使います。エンジンが注文を受け付ける時点で、同意した取引代金の制限と制限価格の範囲内で、要求数量の全体に対応する注文が必要です。対応できなければ、注文全体を取り消します。一部だけを約定したり、残りを買い手や売り手が現れるまで待機させたりすることはありません。約定の判断後も、決済の確認が必要です。決済が終わるまで、アプリは注文をマッチ済みとして表示し、その後に最終結果を表示します。

全量を約定できないことによる取消は、それ自体では取引の認可を使用せず、返金も開始しません。ウォレットがすでに資金をロックして準備した場合、その資金は返金条件を満たすまで利用できないことがあります。

注文が失敗しても、ウォレットは完了した準備の結果を保持します。準備を元に戻したり、支払い済みの準備手数料を返したりしません。未使用のロック済み資金には、通常の期限と返金の処理を適用します。回復処理で新しい注文を自動送信することはありません。

ミントから準備の応答が届かない場合、ウォレットは結果を確認する間、対象の資金を予約したまま保持します。
認可の期限切れや、ほとんどの再試行の拒否だけでは、最初の要求が失敗したとは判断できません。
ウォレットは間隔をおいて確認を再試行します。失敗するたびに間隔を長くし、最長で 15 分にします。ミントが待機時間を指定した場合、ウォレットはその時間に従います。
同じ再試行をミントが何度も拒否した場合、ウォレットは自動の再試行を停止します。そのアラートには、ミントのコードと **再試行** を表示します。資金は予約したままです。

一部のミントの拒否は、ミントが準備を完了しておらず、今後も完了できないことを示します。この拒否を受けると、ウォレットは予約した資金をもう一度確認します。ミントがその資金を使用していなければ、ウォレットは注文の試行を終了し、資金を再び利用できるようにします。注文は送信しません。資金の一部がほかの操作で使用済みの場合、ウォレットは残りの資金を解放します。予約した入力をミントがまだ処理中の場合、ウォレットは待機します。

あるマーケットで前の売り注文が資金を準備している間、アプリは同じマーケットで次の売り注文を開始しません。前の準備が完了するか終了するまで待ってください。その売り注文は **進行中の取引** に表示されます。

## 取引が遅れている場合

接続が切れたことだけでは、取引の失敗は判断できません。ウォレットが応答を受け取る前に、ミントが交換を完了している場合があります。結果が不明な取引を再試行するために、新しい注文を作成しないでください。

同じウォレットとそのローカルデータを保持してください。ウォレットは送信した操作を保存し、回復時に既存の結果を確認します。保存された結果はサーバーの再起動後も残ります。同じ操作の回復で、別の取引を作成してはいけません。

操作が未解決の間は、ブラウザーのストレージやウォレットのローカル記録を削除しないでください。復元フレーズだけでは、処理中の操作や返金の記録をすべて再構築できません。[ウォレットのバックアップと回復](/ja/user-guide/getting-started/wallet-backup/)を参照してください。

決済が完了しない場合、認可の期限後に資金を返金できることがあります。タイムアウトしただけでは、その資金を使用できるようにはなりません。ウォレットは既存の決済結果と返金条件を確認する必要があります。

期限後の回収では、元の資産のロックを解除します。通常の ecash は通貨単位を保持します。
条件付きトークンは、条件と結果集合を保持します。
ミントの交換手数料は引き続きかかります。プロトコルでは、この操作を `refund` と呼びます。
ミント運営者が裁量で補償する方針は、別のものです。
[市場の決着](/ja/user-guide/core-concepts/resolution/)を参照してください。

Web アプリは、閉じるまでウォレットのアラートを保持します。ただし、ウォレットが操作を完了した場合は例外です。その操作の、注文結果が不明であることや資金の回復が保留中であることを示すアラートは閉じられます。未解決のアラートを閉じずに他のアラートを読むには、**次へ**を選択してください。先頭に戻るには、**最初のアラート**を選択してください。アラートを閉じても、回復処理は停止せず、資金も削除されません。

アラートには、ミントが返したコードを表示する場合があります。たとえば **ミントのコード: 11008** です。ミントが注文の準備を拒否した場合、アラートには **注文は完了しませんでした** と表示します。予約した資金は再び利用できます。ウォレットが自動の再試行を停止した場合、アラートに **再試行** を表示します。**再試行** を選択すると、ウォレットは確認をもう一度送信します。

**進行中の取引**には、ウォレットがまだ完了する必要のある操作を表示します。ウォレットのデータが残っていれば、再読み込み後も表示できます。再確認するには、**状態を更新**を選択してください。状態を取得できないことは、取引の失敗を意味しません。決済が確認されても、ウォレットの回復が必要な場合があります。返金条件の成立は、返金の完了を意味しません。ウォレットが処理を完了すると、その操作はこの一覧から外れます。決済が確認された取引は、一覧から外れる前に数秒間 **取引が完了しました。** と表示されます。この一覧は完了した取引の履歴ではありません。

送信した直後の取引をウォレットが完了するまでの間、取引パネルには **ウォレットを更新中…** と表示されます。失敗した取引の返金もこれに含まれます。

注文の決済が確定したことを bitCaster が通知すると、ウォレットはすぐにその結果を反映します。残高、ポジション、ポートフォリオの「資産」タブが更新されます。ページを再読み込みする必要はありません。結果の準備がまだできていない場合、ウォレットは短い間隔をおいて再確認し、その後はより長い間隔で再確認します。

ウォレットの準備と注文の受付は別です。進行中の取引の一覧は、どの段階まで確認できたかを
示します。支払いの準備ができても、エンジンが注文を受け付けた証拠にはなりません。
注文が拒否されても、資金の回復が必要な場合があります。受け付けられた注文も、決済が
確認されるまでは完了した取引ではありません。

## エンジンが確認できる情報

ウォレットは、この注文を認可する ecash の記録を送信します。この記録を proof と呼びます。エンジンはその proof と秘密情報を確認します。復元フレーズ、受け取る出力を利用するための秘密情報、返金鍵、ウォレット内の他の proof は取得しません。

エンジンはウォレットが認可した出力だけを選択できます。その価値を別の宛先へ移動したり、認可の期限を延長したりすることはできません。ただし、決済を遅らせることはできます。その場合、返金が有効になるまで認可済みの資金を利用できないことがあります。
