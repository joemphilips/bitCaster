12 語の復元フレーズをオフラインで安全に保管してください。
取引、支払い、返金が未解決の間は、ウォレットのローカルデータも保持してください。
ウォレットのバックアップは、新しいブラウザーが資金とポジションを見つけるのを助けます。
復元フレーズや、すべてのローカル記録の代わりになるわけではありません。

:::note
ウォレットのバックアップは常に有効です。ウォレットが使った keyset の暗号化された一覧です。
keyset は資産とマーケットの outcome ごとに 1 つあります。マッチングエンジンが保存します。
読めるのは復元フレーズだけです。ecash、額、支出用の鍵は含みません。
バックアップを無効にする設定はありません。サインインも不要です。
:::

## 入金時のリマインダー

ウォレットの復元フレーズを設定の Cashu で表示するまで、トップアップ画面と入金画面に
操作を妨げないリマインダーが表示されます。これらの画面を開くたびに再表示されます。
フレーズを表示すると、現在のウォレットについてリマインダーを確認したことになります。
外部バックアップを作成した証明にはなりません。
別のウォレットに切り替えると、新しいリマインダーが表示されます。

## Nostr鍵は別にバックアップする

Nostr秘密鍵（`nsec`）は、ウォレットの復元フレーズとは別のものです。
復元フレーズでは、この鍵を復元できません。

アプリが作成した鍵は、設定のNostrから「nsecを表示」を選んで確認できます。
リレーからプロフィールを読み込めなくても、鍵はバックアップできます。
警告を確認してから鍵を表示してください。
「nsec をコピー」は他人に見られない場所で使ってください。
表示した鍵は15秒後にぼかされ、60秒後に非表示になります。
コピーした鍵は安全に保管してください。
サポート担当者や他の利用者に共有しないでください。

インポートした鍵は、元のバックアップを保管してください。
設定には、インポートした鍵のバックアップ操作は表示されません。

NIP-07の外部署名アプリを使う場合は、そのアプリで鍵をバックアップしてください。
bitCasterは、その秘密鍵を表示できません。

## 保管する必要がある情報

マッチングエンジンが利用できない場合や、バックアップのアップロードを拒否する場合があります。
その場合も取引は続き、アプリは後でアップロードを再試行します。ecash の記録を proof と呼びます。
proof はローカルストレージだけにあり、バックアップには含まれません。
アップロードが失敗しても、ブラウザーから何も削除しません。

CLI で復元フレーズを使う場合、既定では決定論的に生成された通常の `msat` proof を走査します。
選択した走査範囲内では、mint が署名した新しい通常返金の出力も対象になります。
ただし、その返金の操作履歴は再構築しません。古い返金では、保存済みのローカル記録が
引き続き必要な場合があります。条件を指定した復元には、後述の対応する検出 API が必要です。
Web アプリは、新しいブラウザーでマーケットのポジションを自動で復元します
（「新しいブラウザーでウォレットを開く」を参照）。
進行中のすべての操作で最終結果が確認されるまで、ローカルのウォレットデータベースを保持してください。
復元フレーズによる復元は、未完了の操作を再試行するための保存済み記録の代わりにはなりません。
結果が不明な支払いや取引を解決するために、ブラウザーのストレージを消去しないでください。

## 新しいブラウザーでウォレットを開く

ウォレットを作成していないブラウザーで復元フレーズからウォレットを復元すると、
アプリは資金とマーケットのポジションを mint からすぐに自動で復元します。
Nostr ID やバックアップは不要です。マーケットが多い場合は、数分かかることがあります。

アプリはウォレットを開くたびに、そのウォレットを確認します。
アプリがウォレットを確認または復旧する間、ポートフォリオの「ポジション」「資産」「アクティビティ」タブの上と、
売りタブに、状態の行を 1 つ表示します。この行は、次のいずれかの状態を表示します。

- **ウォレットを確認しています…**：アプリがウォレットを確認しています。
- **ウォレットを復旧しています…**：アプリが資金やポジションを復旧しているか、ウォレットの操作を完了させています。
- **ミントの応答を待っています…**：mint が一部の資金を保留中と報告しています。
- **（時刻）に復旧を再開します**：その時刻まで復旧を待ちます。時刻が今日でない場合は、日付も表示します。

確認が終わると、この行は消えます。
ポートフォリオに **資産はありません** または **アクティブなポジションはありません** と表示するのは、確認が終わった後だけです。
それまでは、アプリがすでに把握している残高を表示したままにします。
このブラウザーのウォレットから読み取っていない資金は、灰色で表示します。
保有資産が不明な間、ヘッダーの残高は **—** と表示します。

エラーの後、復旧は待ってから再び試みます。
復旧の失敗が繰り返された場合は、**ウォレットを復旧できませんでした。** と **再試行** を表示します。
このブラウザーのウォレットのデータを読み込めない場合は、
**ウォレットのデータを読み込めませんでした。** と **再読み込み** を表示します。
ウォレットが開かない場合は、**ウォレットが開いていません。**、**再読み込み**、
Cashu設定の **ウォレットを切り替える** へのリンクを表示します。
そこで、ウォレットの復元フレーズを入力できます。

1 つのブラウザーが開始するこの復元は、24 時間に最大 4 回です。この上限に達すると、
次の復元は 4 回のうち最も古い復元から 24 時間が過ぎるまで待ちます。
待つ間、状態の行に **（時刻）に復旧を再開します** と表示します。
エラーの後に続く復元と **再試行** は、新しい復元として数えません。

新しいブラウザーに移る前に、取引を完了させてください。進行中の注文は資金をロックします。
その注文を完了または返金できるのは、元のブラウザーだけです。
注文が完了した後は、新しいブラウザーがその結果を復元します。

一度に使うブラウザーは 1 つにしてください。このウォレットで別のブラウザーが署名させた
出力をアプリが見つけると、**このウォレットは別のブラウザーでも使われました。
一度に使うのは1つにしてください。** と表示します。

復元では、どの出力がこの復元フレーズのものかを mint に伝えます。mint はこれらの出力を
関連付けることができ、ウォレットが取引したマーケットを知ることができます。
mint は Nostr ID やマッチングエンジンのアカウントを受け取りません。

アプリは各マーケットの最初の 128 counter を確認します。1 つの outcome で約定しない注文が
最初の約定の前に多数ある場合、ポジションが表示されないことがあります。
CLI の `wallet recover-seed --condition-id` で、そのマーケットを復元できます。
アプリがマーケット一覧を確認するのは、復元を開始したときの 1 回だけです。

以前のバージョンのアプリは、どのブラウザーがウォレットを作成したかを記録していませんでした。
そのため、ブラウザーがこのバージョンを初めて開くと、現在のウォレットの復元を実行します。
そのブラウザーがウォレットを作成した場合も同じです。

### 別のブラウザーでの使用を確認する

買い注文と売り注文の前に、アプリは注文で使う予定の出力を別のブラウザーがすでに
署名させていないかを mint に確認します。署名済みの出力があると、アプリはそれらの出力を
飛ばして注文を作り直し、もう一度確認します。その後で注文を送信します。mint がこの確認に
応答しない場合、アプリは注文を送信せず、もう一度試すように表示します。この確認では、
注文の出力を mint に送ります。注文でロックする資金が使う位置の出力も送ります。
これらの出力はまだ署名されていません。

アプリは定期的には mint を確認しません。使用中のすべての keyset を確認するのは、
別のブラウザーでの使用を示す事実があった後だけです。たとえば、別のブラウザーが同じ出力や資金を
使ったために mint が注文を拒否した場合や、注文前の確認で別のブラウザーが署名させた出力が
見つかった場合です。そのとき、ブラウザーは使用中の各 keyset（1 つの資産の mint 鍵）で、
自分の最後の出力より後に別のブラウザーが署名させた出力がないかを確認します。
このような出力が見つかると、アプリはその資金とポジションをこのブラウザーに追加します。

使用中の keyset を確認するとき、ブラウザーは各 keyset の次の 100 個の出力を mint に
送ります。これらの出力はまだ署名されていません。後で別のブラウザーがこれらを使うと、
mint はそれらをこの復元フレーズに関連付けることができます。ウォレットのバックアップは
出力の位置を保存しないため、この keyset の確認は残ります。

注文前の確認で別のブラウザーの出力が見つかった場合や、別のブラウザーが使った出力を
mint が拒否した場合、アプリは **このウォレットは別のブラウザーでも使われました。一度に使うのは1つにしてください。**
と表示します。このような mint の拒否の後は、ウォレットのバックアップも読み直します。

見つけた出力を追加できない場合、アプリは **ミントからポジションを復元できませんでした。**
と **再試行** を表示します。資金は mint に残っています。mint が保留中と報告する資金は、
別のブラウザーの処理が終わるまで待ちます。その資金が必要な注文には
**このウォレットの一部の資金はまだミントで保留中です。注文は送信されていません。後でもう一度お試しください。**
と表示します。

## Web アプリが保存するもの

Web アプリには、独立した 2 つのウォレット機能があります。両方とも既定で有効です。

- ウォレットのバックアップは、ウォレットが使った keyset を一覧にします。常に有効です。
- 表示専用の資産監視は、ポートフォリオを表示します。無効にできます。

使用中のウォレットデータベースはブラウザー内に残ります。
バックアップは、ブラウザーが保存データを削除した場合や、新しいブラウザーでウォレットを開く場合に役立ちます。

## ウォレットのバックアップ

バックアップを読み書きできるのは、12 語の復元フレーズから導出した鍵だけです。
アプリは、ウォレットが新しいマーケットなどで新しい keyset を初めて使ったときに書き込みます。
バックアップに一覧済みのマーケットでの取引や、失敗した注文では書き込みません。
取引がバックアップを待つことはありません。
マッチングエンジンが利用できない場合、アプリは後で再試行します。

読み書きのたびに、マッチングエンジンは復元フレーズに属する request key、時刻、
IP アドレスなどの network metadata を受け取ります。そのため、ウォレットを開いた時刻が
わかります。バックアップのおおよそのサイズもわかります。mint URL、マーケット、出力、
額、支出用の鍵はわかりません。バックアップで資金を使うことはできません。
暗号化は資金を保護します。マッチングエンジンに対するウォレット活動の匿名性を
提供するものではありません。

アプリがバックアップを読めない場合や、バックアップがいっぱいの場合、アプリは
継続して表示されるメッセージを出し、バックアップを変更しません。取引は続きます。
バックアップが新しい形式の場合は、アプリを更新してください。

バックアップを削除するには、CLI の `wallet backup delete` を使います。
復元フレーズが必要です。復元フレーズを保持しているブラウザーは、次のアップロードで
バックアップを再び書き込みます。

mint は、マッチングエンジンでの利用者 ID も資産監視データも受け取りません。mint が
受け取るのは、ウォレット操作に必要な Cashu request だけです。

## 表示専用の資産監視

資産監視は proof を保存せず、マッチングエンジンに資金を使用する権限も与えません。
これは表示専用です。主な目的は、base unit で表した現在と過去のポートフォリオを
best-effort で表示することです。利用者が承認した資産、額、condition、活動の
metadata を使用します。

履歴グラフは、ポートフォリオ評価額の推定変化を表示します。この変化には入出金が
含まれる場合があります。利益や投資収益を示すものではありません。

副次的な目的は、Web アプリが正確に不足している資産を特定することです。その後、
アプリは 1 回だけの制限された復元を実行できます。

ポートフォリオの「資産」タブは、資産監視ではなく、このブラウザーのウォレットから通常の資金を読み取ります。
資金はmintと資産ごとにまとめます。
金額はsatsで表示します。異なるmintの資金は分けて表示します。
未完了の取引や支払いが予約している資金は表示しません。
入金、取引、支払いでウォレットが変わると、このタブはすぐに更新されます。
ローカルのウォレットをまだ読み取れない場合は、資産監視が報告する資金を表示することがあります。
この金額は灰色で表示します。

「ポジション価値」と「合計価値」は、資産監視から取得します。
サービスがウォレットの更新を受け付けたときや、取引が決済されたときに再取得します。
サービスがまだ評価額を作成している間は、何回か再取得します。
サービスは、1 つのアカウントがこれらの値を読み取る頻度を制限しています。
そのため、アプリが続けて再取得するのは 2 回までです。その後は、15 秒に 1 回までです。
この間の変更は、1 回の再取得にまとめます。
このため、「合計価値」は「資産」タブより約 15 秒遅れて更新されることがあります。サービスが評価額を準備している間は、さらに遅れることがあります。
サービスが制限によって再取得を拒否した場合、評価額は読み込み中と表示され、ウォレットのデータは表示されたままです。
アプリは、サービスが示す待ち時間の後、または最大 1 分の間隔をおいて再取得します。
拒否が続く場合は、評価額を取得できない状態として表示します。
評価額が更新中または取得できない状態でも、資金が失われたとは限りません。
価格が不明なポジションも表示されます。
使用できる資金は、ウォレットの支払い画面または取引画面で確認してください。

ポートフォリオの更新中や、受け取りが完了していない間は、最後に取得できた
評価額を表示し続けることがあります。その評価額には、最新ではないことを示します。
使用できる金額を保証する表示ではありません。評価額はメモリー内だけに保持します。
ページを再読み込みするか、ウォレットまたはサインイン中のアカウントを変更すると、
その評価額は消えます。最初から取得できていない評価額を、保存済みの評価額として
表示することはありません。受け取りの進行状況には、ウォレットの現在の処理を
使用します。保存した評価額から進行状況を判断しません。

## Web アプリの復元順序

Web アプリが 1 つの資産の proof を必要とするときは、ローカルのブラウザストレージにある
proof を使用します。ウォレットのバックアップには proof は含まれません。

上記の新しいブラウザーでの復元と、別のブラウザーでの使用の確認だけが、mint に対する
自動の広範な確認です。広範な復元は CLI で利用できます。

取引に Participation Score が必要で、ローカルで利用できる資金が不足している場合、
アプリはウォレットの復元を確認します。復元を利用できない場合は、再試行または
資金の追加を選べます。このメッセージは、他のウォレット資金が失われたことを
意味しません。再試行は、既存の復元上限の範囲内で復元を再確認します。
取引や支払いが未解決の間は、ブラウザーのデータを保持してください。

ウォレットの復元は、単位が `msat` の金銭トークンだけに対応します。
Web アプリはその額を sats で表示します。1,000 msat は 1 sat です。
復元処理は、単位が `sat` のトークンを変換しません。

Counter-zero discovery は選択の手順だけです。完全な復元の前に、期限切れでない CTF
keyset を選択します。これは単独では完全な復元ではありません。

## 複数のウォレット

復元フレーズごとに、独自のウォレットと独自のバックアップがあります。バックアップは
Nostr ID ではなく復元フレーズに属します。ウォレット間で資金が移動することはありません。
Web アプリが表示するのは、現在開いている復元フレーズに対応するウォレットだけです。

- 新しい復元フレーズを入力すると、新しい空のウォレットが始まります。
- 以前使った復元フレーズを入力すると、そのウォレットを開き、mint から復元します。

将来再び開く可能性があるウォレットの復元フレーズは、すべて保管してください。

## 同じウォレットを別のブラウザーで使う

ウォレットの操作には、一度に 1 つのブラウザーを使ってください。
開いたままの別のブラウザーでは、バックグラウンド処理が続く場合があります。
バックアップは 2 つのブラウザーの出力をそろえません。アプリは注文を送信する前に
各注文を mint で確認するため、別のブラウザーに移っても資金を失いません。

Cashu 設定の **ウォレットを入れ替える** は、最初にバックアップを読み直します。
バックアップにまだない keyset をアップロードします。ウォレットのすべての keyset を
一覧にしたバックアップをマッチングエンジンが確認した場合か、より大きなバックアップの
保存をマッチングエンジンが拒否した場合だけ、ウォレットを入れ替えます。後者の場合、
アプリはウォレットを入れ替える前に、現在のウォレットのバックアップが不完全であることを
表示します。続けるには **それでも切り替える** を選び、現在のウォレットを保持するには
ダイアログを閉じてください。後でそのウォレットを完全に復元するには
`bitcaster wallet recover-seed --all-conditions` を使ってください。
マッチングエンジンが利用できない間は、現在のウォレットを保持します。後でもう一度試してください。

結果が出て負けたポジションの削除は、このブラウザーの中だけで行います。後で別の
ブラウザーでウォレットを復元すると、そのポジションが再び表示される場合があります。
価値はなく、再び削除できます。

## CLI のプライバシーと緊急復元

CLI は、プロファイルの確認中にコマンドの送信を中止することがあります。
`daemon profile identity changed during inspection` と表示された場合は、
実行中のウォレット操作が完了するまで待ってから、コマンドを再実行してください。
CLI はプロファイルを修復しません。拒否したコマンドを自動で再実行することもありません。

SQLite が一覧にある WAL または SHM を通常の処理で削除した場合、ファイル一覧確認ごとに
その確認を 1 回だけやり直すことがあります。これは送信前に行います。
この確認では、元のプロファイルの識別情報を保持します。
プロファイルの置換、不正な権限、不正なスキーマは引き続き拒否します。
コマンドの再実行やプロファイルの修復は行いません。

コマンドラインウォレットは、完全なウォレット状態をローカルの永続ストアに保持します。
CLI はまだウォレットのバックアップを書き込みません。CLI だけで使ったマーケットは
バックアップに含まれません。

`wallet backup delete` は、マッチングエンジンにあるウォレットのバックアップを削除します。
`--wallet-seed-hex-file` または `--recovery-phrase-file` を指定してください。
`--realm` で環境を選びます。既定は `bitcaster-production` で、`bitcaster-staging` と、
ローカルの開発用エンジン向けの `bitcaster-local` も選べます。

ブラウザーでの復元が不完全な場合は、`wallet recover-seed` で緊急の
NUT-09/NUT-13 recovery を実行できます。オプションがなければ、通常の `msat` keyset
だけを走査します。`--all-conditions` を加えると、マーケットのポジションも復元します。
公開カタログの各マーケットの最初の 128 counter を確認し、この seed の出力に mint が
署名したマーケットを復元します。`--gap-limit` の既定値は 300 です。
最後に検証した署名の後をさらに走査する場合は、この値を増やしてください。
1 回の要求は最大 300 counter、1 回の実行は最大 4 batch です。

入力には `--wallet-seed-hex-file` または `--recovery-phrase-file` のどちらかを
指定します。phrase file には checksum が有効な英語の BIP-39 phrase を保存し、
所有者以外が読めない権限にしてください。recovery では空の BIP-39 passphrase を
使って標準 seed を導出します。recovery 完了後は file を安全に削除してください。

recovery job は scope と gap limit を固定します。再試行では同じ値を指定して
ください。より深く走査する場合は、新しい recovery ID を使用してください。
結果には走査範囲と、この走査で確認できなかったローカル counter binding を表示します。
走査が完了しても、他の資金がないことの証明にはなりません。gap の後に output が
残る場合があります。

1 つの condition を復元するには `--condition-id <64桁の小文字16進ID>` を使用します。
mint は `nuts.CTF.condition_keyset_filter: true` を宣言する必要があります。
その condition の inactive な過去の keyset も走査します。この capability が
未指定または false の場合は拒否します。全 condition の一覧取得には切り替えません。
このオプションがなければ、通常の `msat` keyset だけを走査します。seed recovery の
前に古い client を停止してください。live authorization は復元しません。
