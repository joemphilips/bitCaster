# LMSR Bot と作成者による資金提供

このページは、bitCasterの自動マーケットメイキングBotについて説明します。人間またはプロのマーケットメイカーの取引モデル、オンライン要件、Mintマッチング、手数料方針については [取引モデルと人間のマーケットメイカー](/ja/technical/architecture/trading-model/) を参照してください。

## コールドスタート問題

新しい予測市場はオーダーブックが空の状態で始まります。トレーダーは空の市場を避け、マーケットメイカーはトレーダーのいない市場を避けます。bitCasterでは、マーケット作成者が既存のCLOBに初期の買い注文と売り注文を出すBotに資金提供できます。

作成者による資金提供は帰属表示のみです。これは引き出し可能な残高、LP持分、損益請求権、残余在庫への権利ではありません。入金は返金不可であり、解決後にBotアカウントに残った担保はオペレーター収益として記録されます。

## なぜLMSRか

bitCasterは、資金提供されたBotにLogarithmic Market Scoring Rule（LMSR）戦略を使います。

| 設計 | v1で採用しない理由 |
|------|--------------------|
| CPMM/FPMM | シンプルだが、作成者の損失が経路依存になり、終端アウトカム付近で流動性の経済性が悪化する。 |
| 外部流動性報酬 | CLOBには自然だが、ローンチ前からプロのマーケットメイカーが必要になる。 |
| コスト関数のない在庫ベース建値 | 実装は容易だが、作成者の損失上限を防御可能な形で示せない。 |
| LMSR | 予算から導かれる明確な損失上限を持ち、カテゴリカルな原子的アウトカム価格に対応し、CLOB指値注文にサンプリングできる。 |

作成者の予算がLMSRの流動性パラメータを決定します。作成者が選ぶのは予算ティアであり、`b`を直接指定することはありません。

## 資金提供フロー

1. 作成者がマーケットを登録し、作成後の資金提供画面に進みます。
2. 作成者は No liquidity、Minimal、Standard、Deep、または Custom 予算を選びます。
3. 資金提供する場合、入金には`fundAmm=true`、作成者公開鍵、マーケット単位、作成者のアウトカム確率分布が付与されます。
4. ウォレットサービスは最初の資金提供入金をマーケットメイカー予算として扱います。最初の資金提供が勝ち、後続の資金提供入金はv1にトップアップ経路がないため通常担保として扱われます。
5. 提供された担保は完全セットの条件付きトークン在庫に分割されます。
6. 完全セット分割が成功した後にのみ、BotはLMSR曲線から建値します。

satマーケットはsatsを使います。USDマーケットはUSセントを使います。一部APIフィールド名には後方互換性のため`Sats`が残りますが、この文脈ではベースアセットのサブユニットを意味します。

## 価格状態

LMSR価格は次の値から計算されます。

- 作成者の登録確率から導かれる seed q
- 決済済みBot取引から再構築される terminal q
- 進行中のロック済みスワップから再構築される pending q

seed qは価格計算専用です。約定済み在庫、決済エクスポージャー、terminal ledger stateとしては記録されません。

確率を`p_i`とすると、seed付きの損失上限は次のようにサイズ決定されます。

```
b = effective_budget / -ln(min(p_i))
```

作成者確率が受け入れ可能な下限を下回る場合、丸めずに拒否します。

## CLOB建値

Botは連続的なLMSR曲線をCLOBの指値注文ラダーへサンプリングします。約定によってqがレベル境界を越えると、Botはラダーをキャンセルして再掲示します。カテゴリカルマーケットでは、原子的アウトカム全体に対して1つのLMSRを使い、コレクション価格は構成する原子の合計になります。

Botはショートしません。資金提供はまず完全セット在庫を作り、後続の受取代金も追加の完全セットへ再分割できます。進行中のNUT-11ロックは、決済・返金・失敗するまで利用不可在庫として数えられます。

## クローズアウト

オラクルがアウトカムを証明した後、Botは新規建値を停止し、オペレーター方針に従って古い保留スワップの完了または強制放棄を待ち、すべてのアウトカム在庫をミントで償還し、残余担保をオペレーター収益として記録します。マーケット作成者に引き出し権や残余請求権はありません。
